# Deploying JobPulse (Render + Neon, free tier)

One container serves both the React app and the API, so they share an origin and the HttpOnly auth cookie works. The root [`Dockerfile`](../Dockerfile) builds the SPA, bundles it into the Spring Boot jar, and runs it on a JRE. [`render.yaml`](../render.yaml) describes the Render service.

**Free-tier behaviour to know about:**
- Render's free web service **sleeps after 15 minutes without traffic**. The first visit after that takes about a minute to wake it.
- Uploaded resumes go to the container's disk, which is **wiped on every redeploy**.
- Neon's free database suspends when idle and wakes in a second or two.

## 1. Create the database on Neon
1. Sign up at https://neon.tech (signing in with GitHub works) and create a project. Pick the region closest to your Render region (e.g. Singapore or Frankfurt).
2. In **Connection Details**, turn **Connection pooling off** to get the *direct* connection string. Flyway migrations need a direct connection.
3. The string looks like `postgresql://USER:PASSWORD@HOST/DBNAME?sslmode=require`. Split it into three values for Render:

   | Render variable | Value |
   | --- | --- |
   | `DB_URL` | `jdbc:postgresql://HOST/DBNAME?sslmode=require` (add `jdbc:`, and **remove** `USER:PASSWORD@`) |
   | `DB_USERNAME` | `USER` |
   | `DB_PASSWORD` | `PASSWORD` |

Type these straight into Render. Never commit them or paste them anywhere public.

## 2. Create the service on Render
1. Sign up at https://render.com with GitHub and give it access to the `jobpulse` repository.
2. **New → Blueprint**, choose the repository and the `main` branch. Render reads `render.yaml`.
3. Fill in the secrets it asks for:
   - `DB_URL`, `DB_USERNAME`, `DB_PASSWORD`: from step 1
   - `ADMIN_EMAIL`, `ADMIN_PASSWORD`: your private admin login (password of 12 or more characters)
   - `DEMO_DATA_PASSWORD`: a shared password for the public demo accounts (8 or more characters). You can put it in your README so visitors can try the app.
   - `JWT_SECRET` is generated by Render automatically.
4. **Apply**. The first build takes about 5–10 minutes. When the logs show `Started JobpulseApplication`, open `https://jobpulse-XXXX.onrender.com`.

## 3. What's on the live site
With `DEMO_DATA_ENABLED=true`, the first start seeds three fictional companies, 14 listings and these demo accounts, all using `DEMO_DATA_PASSWORD`:

| Role | Email |
| --- | --- |
| Candidate | `candidate@example.com` |
| Employer | `hiring@northwind.example.com` (also `talent@kestrel.example.com`, `careers@harborpine.example.com`) |

There is **no demo admin** on a public deployment. The only admin is the one from `ADMIN_EMAIL`. Visitors can register their own accounts too.

To also import real listings, sign in as your admin and call `POST /api/admin/ingestion/run` after adding targets through `JOBPULSE_INGESTION_TARGETS_0_SOURCE=GREENHOUSE` and `JOBPULSE_INGESTION_TARGETS_0_SLUG=<board>` environment variables.

## 4. Updating
`autoDeploy` is on: every push to `main` rebuilds and redeploys. Flyway applies new migrations on startup.

## Troubleshooting
| Symptom | Likely cause |
| --- | --- |
| Build fails at `npm ci` or `mvn` | Check the build log. It's the same build as `npm run build` and `./mvnw package` locally. |
| `JWT_SECRET must be set` | The variable was removed. Regenerate it in Render's environment settings. |
| `Connection refused` / SSL error | `DB_URL` must start with `jdbc:postgresql://` and end with `?sslmode=require`, and use the **direct** (non-pooled) host. |
| `Demo data is enabled: set DEMO_DATA_PASSWORD` | Set it (8+ characters) or set `DEMO_DATA_ENABLED=false`. |
| Out of memory on the free plan | The image already caps the heap for 512 MB. Check that nothing overrides `JAVA_TOOL_OPTIONS`. |
| Login works but you get signed out immediately | You're on plain `http`. The cookie is `Secure` in prod, so use the `https://` URL. |
